# تسريع التطبيق وتقليل الضغط على السيرفر

## المشاكل المحددة

### 1. طلبات API متكررة وغير ضرورية
- **DashboardScreen**: يستدعي 5 API calls في `Future.wait()` في كل مرة (market summary, indices, movement classification, gold, currency) بدون TTL كافٍ
- **StocksScreen**: يستدعي `_refreshData()` عند أي تغيير في cache يبدأ بـ `stocks_` أو `stock_movement_` - يتضاعف مع cache subscription
- **PollingService**: يطلب market status كل 3 دقائق بشكل منفصل عن Dashboard polling
- **MobileApiService**: يخزن dashboard/news في SharedPreferences (JSON ضخم) + ApiCacheManager = تخزين مزدوج

### 2. JSON decode على الـ main isolate
- تحليل JSON كبير في الـ main thread يسبب تعليق UI (jank)
- بيانات الأسهم والأسعار التاريخية تُعالج في main thread

### 3. إعادة بناء UI غير ضرورية
- `setState()` مع بيانات قائمة في الـ cache تُعيد بناء الـ widget tree كاملاً
- `_refreshWatchlist()` في WatchlistScreen يُنشئ Future جديد في كل cache update

### 4. SharedPreferences + ApiCacheManager ازدواجية
- نفس البيانات مخزنة في اثنين بأماكن
- يُبطئ التهيئة لأن كل `getDashboard` يقرأ من SharedPreferences أولاً

### 5. غياب الـ Isolate لمعالجة JSON

## الحل المقترح

### Phase 1: خدمة Rate Limiting ذكية (RequestThrottleService)
**ملف جديد**: `lib/services/request_throttle_service.dart`
- Queue للطلبات بـ max concurrency = 3
- deduplication: نفس الـ endpoint لا يُطلب مرتين في نفس الوقت
- circuit breaker: بعد 3 فشل متتالي، يتوقف لـ 60 ثانية

### Phase 2: Isolate-based JSON parsing
**ملف جديد**: `lib/core/json_isolate.dart`
- `compute()` لكل JSON يتجاوز 10KB
- يمنع تعليق UI عند parse البيانات الكبيرة

### Phase 3: تحسين ApiCacheManager - إضافة Persistent Cache
**ملف محدَّث**: `lib/api/cache_manager.dart`
- إضافة SharedPreferences persistence للـ cache (بدلاً من ازدواجية MobileApiService)
- TTL موسعة: market data → 3 دقائق (من 2)، stock list → 10 دقائق (من 5)
- إضافة `pendingRequests` map لمنع duplicate simultaneous requests

### Phase 4: تحسين PollingService
**ملف محدَّث**: `lib/services/polling_service.dart`
- إزالة market status timer المنفصل (3 دق) - دمجه مع dashboard poll
- زيادة interval السوق المفتوح من 5 دقائق → 7 دقائق
- إضافة backoff تلقائي عند الفشل

### Phase 5: تحسين DashboardScreen
**ملف محدَّث**: `lib/screens/dashboard_screen.dart`
- استخدام `compute()` لـ JSON parsing
- تقليل `Future.wait()` من 5 calls → 3 (دمج market summary مع indices)
- تبديل cache subscription لـ debounce بـ 500ms بدل immediate refresh

### Phase 6: تحسين MobileApiService
**ملف محدَّث**: `lib/api/mobile_api.dart`
- إزالة SharedPreferences caching المزدوج من getDashboard/getNews
- الاعتماد الكلي على ApiCacheManager الجديد المع persistent support

### Phase 7: تحسين Local Database للبيانات التاريخية
**ملف محدَّث**: `lib/api/local_database.dart`
- إضافة `api_cache` table لتخزين JSON الكبير في SQLite بدل SharedPreferences
- max size: 5MB per entry مع LRU eviction

## الأثر المتوقع
- **تقليل API calls**: ~60% أقل في ساعة (من ~70 call/h → ~28 call/h)
- **إزالة UI jank**: JSON parsing خارج main thread
- **تحسين startup**: البيانات من SQLite cache قبل أي network request
- **تقليل memory**: إزالة تخزين مزدوج في SharedPreferences
